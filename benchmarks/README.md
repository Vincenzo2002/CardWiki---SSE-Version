# JMH benchmarks with Maven

The Maven project has a parent POM at the repository root and two modules:

```text
pom.xml
backend/                  application code and existing tests
benchmarks/
  pom.xml                 JMH 1.37, annotation processor, and Shade 3.5.3
  src/main/java/          classes with @Benchmark methods
  target/benchmarks.jar   executable JAR generated by Maven
```

The frontend is still managed with npm. JMH is a dependency of the `benchmarks`
module only.

## Build

Use **JDK 11** for both Maven and benchmark execution, as required by the backend.
On macOS:

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 11)
export PATH="$JAVA_HOME/bin:$PATH"
mvn -version
```

Run from the **repository root**:

```sh
mvn clean package
```

This command also runs the backend tests. To rebuild the benchmarks without
running the tests:

```sh
mvn -pl benchmarks -am clean package -DskipTests
```

`-am` also builds the backend required by the benchmarks. There is no need to
install the backend in the local Maven repository first.

The backend produces both `backend/target/backend-0.0.1-SNAPSHOT.jar`, the
executable Spring Boot JAR, and `backend/target/backend-0.0.1-SNAPSHOT-plain.jar`,
used as a dependency by JMH. The `plain` JAR exposes classes on the standard Java
classpath; in the Spring Boot JAR, application classes are under `BOOT-INF/classes`.

## Run

List the available benchmarks:

```sh
java -jar benchmarks/target/benchmarks.jar -l
```

Run all benchmarks, or select one by name:

```sh
java -jar benchmarks/target/benchmarks.jar
java -jar benchmarks/target/benchmarks.jar 'CategoryMapperBenchmark.mapCategories'
```

Quick installation check (the timings from this smoke run are not reliable measurements):

```sh
java -jar benchmarks/target/benchmarks.jar 'CategoryMapperBenchmark.mapCategories' \
  -p size=10 -wi 1 -i 1 -w 100ms -r 100ms -f 1 -foe true
```

To export a measurement using the benchmark's configuration:

```sh
java -jar benchmarks/target/benchmarks.jar 'CategoryMapperBenchmark.mapCategories' \
  -rf json -rff benchmarks/target/results.json
```

## Add benchmarks

Create new classes in `src/main/java/at/ac/tuwien/sepm/groupphase/benchmarks/`.
Use an explicit Java package and annotate public methods with `@Benchmark`.
The compiler configuration explicitly enables `jmh-generator-annprocess` to
generate the harness and `META-INF/BenchmarkList`.

`CategoryMapperBenchmark` measures the backend's MapStruct mapper on lists of
10, 100, and 1000 categories, without starting Spring or a database. Input data
is prepared in `@Setup`; each measured operation converts a whole list and
returns the result to JMH to prevent the JIT from eliminating it.
Values are therefore in **ns per list**, rather than per category.
The default configuration uses 3 warmup iterations, 5 measurement iterations
lasting one second each, and 2 separate JVM forks for each list size.

For new measurements, prepare inputs outside the measured method and return
the result or consume it with `Blackhole`. Place benchmark-specific resources
in this module's `src/main/resources/` directory.

## Store SSE results

Copy outputs out of `target/` before running `mvn clean`, which deletes them.
Store baseline results in
[sse-reports/baseline/jmh/](../sse-reports/baseline/jmh/) and improved results in
[sse-reports/sse-improvements/jmh/](../sse-reports/sse-improvements/jmh/),
depending on the application version measured. Record the executed commit,
command, and environment in a short English note, as described in the
[report guide](../sse-reports/README.md).

Follow the [branch workflow](../README.md#branches-and-improvements): add missing
benchmarks to `baseline`, then bring them into a temporary branch from `master`
to measure the current version with the same tests. Submit improvements and
their results through pull requests into `master`. The results directory name
does not refer to a separate development branch.

References: [JMH](https://github.com/openjdk/jmh) and
[additional JARs with classifiers](https://maven.apache.org/plugins/maven-jar-plugin/examples/attached-jar.html).
